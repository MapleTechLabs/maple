Maple ingests OpenTelemetry over OTLP, on HTTP or gRPC, so any OTLP exporter works without a Maple-specific plugin. Each guide below installs the SDK, points it at the ingest endpoint with an ingest key from **Settings → Ingestion**, and checks that the first trace arrives.

If you are new to Maple, the [Quickstart](/docs/getting-started/quickstart) gets a first trace in about five minutes. The [maple-onboard](https://github.com/MapleTechLabs/maple/tree/main/skills/maple-onboard) skill can do the same setup from a coding agent.

## Anything that speaks OTLP

If your language or framework is not listed, point its OpenTelemetry SDK (or an OpenTelemetry Collector) at the ingest endpoint with the standard environment variables. Ingest keys are scoped to one organization and can only write telemetry. Only the public key (`maple_pk_…`) is safe to ship in client code. Keep the private key (`maple_sk_…`) in an environment variable or a secret store. See [Authentication](/docs/reference/authentication).

<TelemetryFlow />

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT="https://ingest.maple.dev"
export OTEL_EXPORTER_OTLP_PROTOCOL="http/protobuf"
export OTEL_EXPORTER_OTLP_HEADERS="Authorization=Bearer YOUR_INGEST_KEY"
export OTEL_SERVICE_NAME="my-service"
```

Maple accepts OTLP over HTTP (protobuf or JSON) and OTLP over gRPC on the same host and port 443. Set `OTEL_EXPORTER_OTLP_PROTOCOL` to match the exporter package you installed: `http/protobuf` for an HTTP exporter, `grpc` for a gRPC one.

Maple reads the standard semantic conventions. The attributes it relies on for the service map, error grouping and sampling-aware throughput are listed in [OpenTelemetry conventions](/docs/concepts/otel-conventions).

To develop against a local sink instead of the cloud, run [Maple Local](/docs/local-mode) and point the endpoint at `http://localhost:4318`.

## Data regions

Maple Cloud runs in two regions. You choose your organization's region during onboarding, and it cannot be changed afterwards. Send telemetry to the ingest endpoint of your organization's region, with an ingest key created in that region's dashboard. A key from one region is rejected by the other.

| Region                     | Dashboard                  | Ingest endpoint               |
| -------------------------- | -------------------------- | ----------------------------- |
| United States              | `https://app.maple.dev`    | `https://ingest.maple.dev`    |
| European Union (Frankfurt) | `https://app.eu.maple.dev` | `https://ingest.eu.maple.dev` |

Every guide on this site uses the US endpoint. For an EU organization, replace `ingest.maple.dev` with `ingest.eu.maple.dev`. Nothing else changes. See [Regions](/docs/reference/regions) for details and [EU hosting](/eu) for what the EU region covers.

If your stack has no guide, [open an issue](https://github.com/MapleTechLabs/maple/issues) and tell us what you run.
